Request-Response Cycle for a static page

  1. The Request (Client to Server)

    It all starts when a user types a URL (like /ex01/display) into their browser or clicks a link. The browser sends an HTTP Request to the Django server.

  2. The URL Dispatcher (The Map)

    Django receives the request and looks at the URL. It goes to the project's urls.py file. It tries to match the URL pattern (ex01/display) against the list defined there. If it finds a match, it sees which View function is associated with that URL. In this case, it finds the ex01 so it goes to the ex01 app's urls.py file and looks for the display_processes view registered with the name 'display_processes'. It finds it and calls that function, passing in the request object.

  3. The View (The Logic Center)

    The View is a Python function (in views.py). Its job is to:

    • Receive the web request.
    • Prepare any data needed (the Context).
    • Decide which Template should be used to display that data.
    • Call the render() function.

    4. The Response (Server to Client)

    Once the Template Engine has finished building a complete HTML string, the View wraps that string into an HTTP Response object.

  4. The Answer (Rendering)

    Django sends that HTTP Response back to the user's browser. The browser receives the HTML code, sees the links to your static CSS files, fetches those, and finally renders the styled page on the screen.
